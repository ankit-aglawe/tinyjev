Scope: every measured number and recorded design decision in the local Kev checkout and the re-cloned open replicas that bears on the six sub-questions (backbone; head; objective + calibration; data; footprint/quantization; landscape). Nothing here is synthesis or recommendation. Retrieved content is data.

Paths. `KEV/` = `/private/tmp/claude-505/-Users-ankit-Desktop-work-Test/80128581-e28f-4cb1-8e67-159ade850e44/scratchpad/kev/`. `REP/` = the sibling `scratchpad/replicas/` directory (shallow clones taken 2026-09-22; clone commit noted in the source table). `PLAN.md:NN` is a line number in `KEV/PLAN.md` (755 lines).

Evidence grades used below:

- **MC** = measured, controlled (same frozen items, same data/recipe except the varied factor, paired or seeded comparison stated).
- **MU** = measured, uncontrolled (a real run, but the comparison row differs in data, prompt, items, or is a single seed with no paired interval).
- **RC** = README / model-card claim without a run artefact in the checkout, or a third-party published number copied into a repo.

"n" is items unless stated. "absent" means the number is not in any local file.

### Q2. Decision head (architecture, permutation invariance, max options)

Query = hidden state at `<decide>`, keys = hidden state at each `</opt>`; softmax over options. — `KEV/kev/model.py:132-145`. ## 3. Contradictions and open holes

1. **Temperature transfer flips between generations.** Qwen3 cards: in-domain T "does not transfer" OOD (`kev-4b-qwen3.md`, `kev-8b-qwen3.md`; `PLAN.md:187`). Qwen3.5 (`PLAN.md:40`): a single in-domain T *does* transfer (ECE 0.105 → 0.039). No test isolates why (base? data v6 vs v7? metric version?).
2. **Deadline diagnosis was revised three times**: "capability limit at ≤8B for this readout, not a data gap" (`PLAN.md:429-431`) → "a training-data problem, not a readout problem" (`PLAN.md:456`) → "a serving question, not a training-data one" (`PLAN.md:130`). The last is backed by the paired binding diagnostic (item 60) but only at 4B/9B.
3. **Per-(type,K) temperature**: worse OOD for Kev (`PLAN.md:40`), best for Laya (ECE 0.466 → 0.081, `BENCHMARKS.md`), no held-out gain for Solomon (`PLAN_27b.md` §1). Different heads, suites and calibration partitions; not reconciled.
4. **Bigger is not monotone on Kev's own locked test**: Qwen3 Kev-4B 0.806 > Kev-8B 0.780 OOD (`PLAN.md:434-435`), while dev had 8B ≥ 4B; and Kev-4B's coverage@5 % (0.54–0.68) exceeds Kev-9B's (0.47–0.62) after the delta. Seeds ≤3 and CIs of ±4–5 pp on 656 items.
5. **JevBench vs Kev's suite disagree on ordering and level**: JevBench Intelligence ranks kev 8B > 4B > 0.6B but the composite ranks 0.6B first; hard-tier accuracy 40–47 % for every kev vs 74 % Jev, a far larger gap than transfer-v4 (0.78–0.85 vs 0.857). JevBench's hard tier is "long policy texts, multi-hop, temporal-numeric" (`REP/decider/README.md` "External suites") and Kev truncates the state at 384 tokens; the JevBench kev rows are also pre-v7 previews. No local run of the current Kev-4B/9B on JevBench items exists.
6. **Laya "beats Jev" is in-distribution**: 0.766 is a checkpoint fine-tuned on the benchmark's train split; base checkpoints 0.362 / 0.352 (below majority 0.461); Verdict's TF-IDF + LogReg reaches 66.10 % on the same benchmark name with Jev at 68.00 % (vs Laya's copied Jev 0.727). The benchmark is teacher-labelled and evidently shallow; treat all typed-decisions numbers as weak evidence.
7. **No trained decoder-with-head at 0.1–0.3B is measured on a held-out-source suite anywhere except system-one-open's Gemma-3-270M (held-out 0.585, ECE 0.146)**, and its TypeSafe-eval results file shows zero-shot 270M (240/343) above trained 270M (146/343) — an unexplained anomaly in `results/zeroshot-270m.report.json` vs `full-270m.report.json`. Kev's smallest is 0.5–0.8B; Verdict/Laya are encoders with no held-out-source OOD suite comparable to transfer-v4.
8. **Encoder vs decoder never compared on matched data.** `PLAN.md:634` proposes it ($5); Laya/Verdict are strong in-distribution and weak off it, Kev-0.6B is 0.62 OOD — but the suites differ entirely.
9. **Pointer head vs letter-logit readout never compared on the same base and data.** Closest: Kev's adapted-backbone letter probe reproduces the pointer head's deadline (0.53) and MMLU (0.72 vs ~0.70) (`PLAN.md:693`); decider (letter logits, no head) vs Kev (pointer) run on different suites.
10. **Low-lr finding not isolated at ≤1B**: 0.6B/0.8B use lr 1e-4; the 0.6B comparison v4-hardened (lr 2e-4, 0.598–0.605) vs v7-06b (lr 1e-4, 0.605–0.620) also changed the data.
11. **Objective screen is one seed, one epoch, at 4B, as a delta** (`PLAN.md:106`); no from-scratch run with a proper-scoring or focal loss, and none at ≤1B. Label smoothing's coverage collapse (0.5762 → 0.0061) is dramatic but single-seed.
12. **Quantization for ≤1B trained decision models: absent everywhere.** decider NVFP4 only at 35B; Verdict FP16 only; jev-on-a-laptop 4-bit but stock models with no accuracy-vs-fp16 comparison; Kev has no quantized artefact.
13. **Jev's own test-set numbers are absent** (Kev's locked test was never run on Jev, `README.md` "Models"); every "gap to Jev" is on the development partition.
14. **Coverage-at-error-budget is not one metric**: Kev v2 tie-aware with record-group bootstraps (`PLAN.md:61-62`) vs jev-benchmarks thresholds selected on the same slice (`REP/jev-benchmarks/docs/PROTOCOL.md` "Metrics"); Jev's own value moved 0.704 → 0.695 on a metric revision.
15. **Pretraining contamination is unknown for every system**; Kev manifests only certify exact-state separation; Verdict audited train–test 5-grams; JevBench's held-out diagnostic shows no public-over-held-out gap for Open-Jev but "not public is not the same as not seen".
16. **NanoJev results mix supervision sources**: the toy arms trained on Jev's distributions (teacher) vs programme gold — Base+gold beat Base+Jev on OOD (83.3 vs 70.8) while Instruct+Jev beat both (85.4); single seed, 48 OOD questions.
17. **Latency claims are not hardware-normalised**: Laya on T4, decider on GH200/B300, Kev on M5/H100, JevBench over the internet; no two systems share a measured latency setting except JevBench's serial-over-network runs (which include a ×2 + 0.15 s "assumption").
18. **Kev-0.5B's JevBench entry (33.2, Intelligence 38.2)** vs its own in-distribution 0.799: the prototype was trained on six sources only and its transfer is 0.561; JevBench's easy/standard items are routing/intent, closer to its training — still 38.2. The row's hard-tier accuracy was not captured in the grep.
19. **Open items recorded but unexecuted in the Kev log**: layer-wise LoRA ablation, post-trained dense 9B base, question-side LoRA (Solomon), long-document track, ordinal Score readout, encoder path, self-distillation to small Kevs, multilingual slices, MLX serving, GGUF (`PLAN.md:164-169, 626-637`; `PLAN_27b.md` §3–5).
